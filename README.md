## 买之前要准备什么：一台 ECS 和实名认证

两样东西：一个完成实名认证的阿里云账号，和至少一台云服务器 ECS。官方购买指南把“至少有一台 ECS”列为开通云数据库 Redis 版的前提条件。

原因很实际：Redis 实例主要供你的应用走内网访问，官方建议实例和 ECS 选在同一地域、同一可用区，延迟最低。更关键的是，ECS 和 Redis 之间的内网数据传输免费。缓存业务的特点就是流量大，如果这部分按流量计费，账单会很难看——内网免费这条，等于砍掉了缓存方案里最大的一块隐性成本。

账号层面还有个容易忽略的上限：每个实名认证的阿里云账号最多开通 10 个按量付费实例。需要更多实例或更高容量规格，要走工单申请，充值解决不了。

## 容量和架构怎么选：先想清楚数据量和读写比例

选型思路一句话：标准缓存、预算优先，选 Redis 开源版内核；数据量大、想用持久化省成本，看 Tair 企业版；架构上生产环境默认高可用，读多写少加读写分离，单机装不下再上集群。

两个内核的差别在存储介质上最直观。Tair 企业版支持内存、持久内存、磁盘三种介质，按官方说法，合理选型能省 30%~70% 的存储成本。持久内存和磁盘的速度不如纯内存，但价格低得多，适合把 Redis 当持久化数据库用的场景——甚至可以简化架构，只用 Tair 同时承担缓存和持久化两个角色，省掉一套独立的持久化数据库。

架构有四种：单节点、高可用、智能读写分离、分布式（集群），支持架构之间不停机转换，买错了以后能调。几个关键数字：高可用是主备架构，主节点故障自动切换，官方标注最高 99.99% 的 SLA；读写分离最多挂 9 个只读节点，接入不需要改代码；集群最大 256 分片，官方数据是可支撑高达 7000 万次/秒的低时延请求。米哈游的排行榜、雪球每天近千万级 QPS 峰值读写都跑在这套产品上——这些案例说明上限足够高，不代表你需要一步买到那么大。

按场景给个直接的判断规则：

- 自己测试或跑 demo → 单节点 + 按量付费，用完释放
- 正式业务 → 高可用 + 包年包月，容量按当前用量留少量余量
- 读多写少、主库 CPU 吃紧 → 高可用基础上加读写分离
- 数据量超过单机内存上限，或并发持续走高 → 集群

## 续费、变配和欠费：买完之后最容易踩的三个坑

结论先给：包年包月记得开自动续费；包年包月周期内只能升配不能降配；按量付费欠费超过 7 天实例会被释放，数据找不回来。

**续费。** 包年包月支持自动续费，在控制台里设置，比到期手动续省心。到期未续费会停服，7 天内续费成功服务自动恢复；超过 7 天视为主动放弃，实例被释放，数据删除且不可恢复。释放前 1 天会有短信和邮件提醒，但别指望这条提醒救你，收到提醒再操作已经很被动。

**变配。** 按量付费随时升降配，按小时结算；包年包月在服务周期内只支持升配，想降配要等到期续费时一并操作。变配过程中实例会发生秒级闪断，挑业务低峰期做。

**欠费。** 按量付费实例欠费后 24 小时内充值，服务不受影响，这期间照常计费；超过 24 小时未处理会停服并停止计费；7 天内充值补足可自动恢复；超过 7 天实例释放，数据不可恢复。建议顺手开启余额预警，余额低于设定值会收到短信或邮件提醒，比你自己记着看账单靠谱。

## 常见问题

**没有 ECS 能直接买云数据库 Redis 版吗？**
官方购买指南把“至少有一台 ECS”列为前提条件。你的应用总要有个地方运行才能连 Redis，如果连 ECS 都还没有，说明业务还没部署，先买 ECS 再配 Redis，顺序别反。

**云数据库 Redis 版和 Tair 是什么关系？**
是同一条产品线的新旧叫法。现在官网叫“云数据库 Tair（兼容 Redis®）”，提供 Redis 开源版和 Tair 企业版两种内核，都兼容 Redis 协议，客户端和代码不用改。

**买错了容量怎么办？**
按量付费支持实时升降配；包年包月周期内只能升配，降配要等到期续费时操作。所以包年包月下单时宁可保守，容量不够升配很快，买大了退不了。

**ECS 访问 Redis 的流量要单独收费吗？**
内网流量免费。这也是官方建议同地域部署的原因之一。

**实例创建好了但连不上怎么办？**
先检查白名单。实例默认不允许任何内网或公网 IP 访问，把客户端 IP 加进白名单才能建立连接。
